# TIDY: Temporal Indexing for Die-Young Objects

TIDY is an in-memory temporal index for high-ingestion workloads of short-lived intervals. It maps intervals to the (end, duration)
space, splits them into short- and long-lived partitions and stores each partition in a B-Rail, a cache-friendly, append-only index with O(1) amortized insertions.

## TL;DR

```bash
./run.sh
```

The script handles everything from building the Docker image to plotting.

## Requirements

- Linux on x86-64 with AVX (the code is compiled with `-mavx`), and Docker.

To run natively (set `NATIVE=1`, see Running below), the host needs:
- g++ (C++17), make, Boost headers (`libboost-dev`)
- Python 3 with the packages in `requirements.txt`
- `curl` (used by `run.sh` to download the datasets)

The paper's experiments ran on an Intel Core i7-14700K (5.6 GHz) with 128 GB RAM,
Ubuntu 24.04.3 LTS, g++ 13.3.

## Datasets

Five real datasets (about 5.3 GB in total, 1.9 GB compressed) are archived on Zenodo:
<https://doi.org/10.5281/zenodo.23094082>.

`run.sh` downloads and decompresses the datasets automatically. To fetch them yourself, download the `.dat.gz` files from Zenodo, decompress them, and place them at:

```
data/static/TAXIS.dat
data/static/BIKES.dat
data/static/FLIGHTS.dat
data/static/WEBKIT.dat
data/static/WILDFIRES.dat
```

Each line is `start end [attribute]`. The optional attribute field is unused by the experiments. `run.sh` turns every dataset into a stream with 1,000 interleaved queries (`data/stream/generate_streams.py`). Missing datasets are skipped with a warning.

The synthetic one-billion-interval datasets of Section 5.5 and 5.6 are generated by `run.sh` (`data/stream/synthetic/`).

## Running

```bash
./run.sh [TARGET ...]
```

`TARGET` chooses what to run:

| Target | What it runs | Paper | Time |
|---|---|---|---|
| `all` (default, no argument) | `real` + `synthetic` | everything below | ~44 h |
| `real` | every experiment on the five real datasets | Figures 2, 6–10, Tables 2–9 | ~6 h |
| `synthetic` | the one-billion-interval experiments (`te_skew`, `poisson_duration`) | Table 10, Figure 11 | ~38 h |
| `<experiment>` | a single experiment by name, e.g. `competitors` (names in [Experiments in the paper](#experiments-in-the-paper)) | that figure/table | varies |

Several targets can be given at once, e.g. `./run.sh live_vs_dead brail_variants`. Before the experiments, `run.sh` always builds the code, downloads datasets, and generates queries and streams. Existing streams are reused. `competitors` reads the `brail_variants` log, so run `brail_variants` first. Each experiment writes its figures (PDF) and tables (CSV) into its own folder, `experiments/<experiment>/`.

**Docker or native.** By default `run.sh` builds a Docker image and re-runs itself inside the container, so the host only needs Docker. To run directly on the host, set `NATIVE=1` (see [Requirements](#requirements)):

```bash
NATIVE=1 ./run.sh [TARGET ...]
```

The first native run creates a `.venv/` and installs `requirements.txt` into it.

**Options** (environment variables):

| Variable | Effect |
|---|---|
| `NATIVE=1` | run on the host instead of in Docker |
| `SKIP_CACHE=1` | skip the cache-miss experiment (Figure 10) |

### Cache-miss experiment (Figure 10)

Figure 10 reads hardware performance counters. On the host run

```bash
sudo sysctl -w kernel.perf_event_paranoid=1
```

before `./run.sh` (the Docker path already requests the needed `--cap-add PERFMON --security-opt seccomp=unconfined`). To skip this
experiment set `SKIP_CACHE=1`. If the counters are not readable, `run.sh` skips this experiment with a warning and continues.

## Resources and running time

Rough estimates on the hardware above:

| Part | Time | Disk | Memory |
|---|---|---|---|
| Real datasets (`real`) | ~6 h, about half of it the R*-tree | ~40 GB of streams | 16 GB (TAXIS peaks at ~10 GB) |
| Synthetic (`synthetic`) | ~38 h (`te_skew` ~6 h, `poisson_duration` ~32 h), dominated by the R*-tree | ~270 GB of streams | 64 GB (the R*-tree peaks above 46 GB) |

`run.sh` checks the machine's RAM first. A real dataset that needs more RAM than the machine has is skipped, as are the synthetic experiments below 64 GB. Each skip is reported when it happens.
